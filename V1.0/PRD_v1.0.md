Security, Multi-Tenant Isolation & Guardrail Rules ### 4.1 Row-Level Security (RLS) Metadata Tagging (Layer 14) Every document chunk parsed by LlamaParse and stored in ChromaDB / Supabase pgvector must include mandatory metadata attributes to maintain absolute multi-tenant tenant isolation: ```json { "tenant_id": "dept_engineering_sre", "data_classification": "restricted", "allowed_roles": ["admin", "sre_lead"], "source_document": "k8s_runbook_v2.pdf" } ``` At runtime, the RAG retrieval pipeline automatically injects a hard context filter: $$\text{Filter} = \text{Match}(\text{tenant\_id} == \text{User.tenant\_id}) \land \text{Match}(\text{role} \in \text{User.roles})$$ ### 4.2 Deterministic Cache Bypass Filter (Layer 3) To prevent Semantic Cache Poisoning, incoming user queries pass through a token scanner before querying Redis / GPTCache: * **Rule:** If the query contains high-impact compliance or critical environment tokens (`HIPAA`, `GDPR`, `PROD`, `DELETE`, `FIREWALL`), the semantic similarity match is bypassed entirely, forcing a fresh LLM generation run. --- ## 5. Human-In-The-Loop (HITL) & Infinite Loop Breaker Matrix ### 5.1 Agentic Infinite Loop Breakers (Layer 5/6) * **Max Loop Limit:** Set to `max_iterations = 3` inside LangGraph. * **Trigger Condition:** If the Auditor/Reflection Agent rejects the Scribe Agent's response 3 consecutive times, the state machine terminates the loop, updates state status parameters to `NEEDS_HUMAN_REVIEW`, and routes the context block directly to the HITL Queue. ### 5.2 HITL Action Matrix | Execution Action | Risk Level | Automated Agent Execution? | HITL Requirement | | :--- | :--- | :--- | :--- | | Query Logs / Runbooks | Low | Yes (100% Automated) | None (Notify only) | | Draft Incident RCA Report | Medium | Yes (100% Automated) | Engineer Review | | Restart Staging Service | Medium | Conditional | Single-Click Approval | | Apply Firewall / DB Patch | High / Critical | NO (Blocked) | Mandatory Dual-Role Sign-Off |
